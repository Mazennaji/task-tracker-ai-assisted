# Reflection

For this milestone I used AI assistance throughout the workflow — drafting user stories, generating initial implementation code for both the backend and frontend, writing and debugging pytest tests, and reviewing design tradeoffs before committing to an approach. AI was most useful in the drafting stages: turning a rough feature idea ("add due dates") into a scoped, testable plan with explicit validation rules, and generating first-pass code for repetitive patterns like Pydantic model fields, query parameter handling, and React chip components. It also sped up debugging — when a test unexpectedly failed after adding tags, pasting the failing test alongside the relevant handler let AI correctly diagnose that the update logic was overwriting tags whenever the field wasn't explicitly sent, which would have taken longer to trace manually.

AI slowed me down in one clear moment: the first tags implementation defaulted to a fully normalized relational design (separate `Tag` table, join table, migrations) when a simple list field on the task record would have met every requirement for this milestone. I spent time reviewing and partially implementing the more complex version before stepping back, rereading the actual acceptance criteria, and rewriting the prompt to explicitly constrain the data shape. That detour was a useful reminder that AI tends to reach for the "more correct at scale" answer even when the task calls for the smallest thing that works.

The place where my review changed the result most was the overdue-detection logic. AI's first version treated any task with a past due date as overdue, full stop — including tasks already marked Done. That's technically simpler, but it produces a misleading board (completed work flagged as "late"). I corrected this in the user stories before implementation, then again caught a frontend/backend mismatch later where the UI's overdue badge used slightly different logic than the API — a discrepancy that only surfaced during manual browser testing, not from the test suite alone.

Overall, the workflow worked well when I treated AI output as a strong first draft rather than a finished answer: useful for generating structure and catching syntax-level mistakes quickly, but requiring my own judgment on scope, edge cases, and consistency between layers of the application.
